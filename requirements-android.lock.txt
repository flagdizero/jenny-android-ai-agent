# requirements-android.lock.txt — LOCKFILE GENERATO (non modificare a mano)
#
# (a) Provenienza: pin esatti (==) fotografati dalle versioni GIÀ INSTALLATE
#     nell'ambiente di test funzionante `.venv-test` (quello che oggi passa
#     `pytest -q`). NON è una risoluzione fresca da PyPI: le versioni qui sono
#     esattamente quelle contro cui il codice è testato.
#
# (b) Rigenerazione (dalle versioni installate/testate, senza rete):
#       for p in $(grep -vE '^\s*#|^\s*$' requirements-android.txt \
#                  | sed -E 's/[<>=!~].*//'); do \
#           .venv-test/bin/python -m pip show "$p" \
#           | awk '/^Name:/{n=$2}/^Version:/{print n"=="$2}'; done
#     e aggiungere le dipendenze transitive risolte nello stesso ambiente
#     (vedi sezione "Transitive" sotto). In alternativa, quando si ha accesso
#     di rete e si vogliono aggiornare i vincoli:
#       uv pip compile requirements-android.txt -o requirements-android.lock.txt
#     (ATTENZIONE: quest'ultimo risolve da PyPI, cambia le versioni).
#
# (c) `requirements-android.txt` resta la SORGENTE DEI VINCOLI (range su major).
#     Questo file è l'OUTPUT rigenerabile con i pin esatti. Se cambi un range
#     là, rigenera qui. Il build APK (android/app/build.gradle.kts) installa
#     QUESTO file, così due build a distanza di tempo impacchettano le stesse
#     wheel.
#
# Granularità: a differenza di requirements-android.txt (solo top-level, 12
#     pacchetti diretti), questo lock include ANCHE le dipendenze transitive
#     pinnate, perché è ciò che rende il build davvero deterministico (senza
#     pin sulle transitive, pip le risolverebbe di nuovo a ogni build). Le
#     transitive elencate sono la chiusura runtime dei top-level nell'ambiente
#     testato; i pacchetti solo-di-test (pytest, pluggy, iniconfig, packaging,
#     Pygments, pytest-asyncio) sono esclusi perché non finiscono nell'APK.
#
# Uso in CI (.github/workflows/ci.yml) — OPZIONALE, non ancora attivato:
#     per far testare a CI esattamente ciò che finisce nell'APK, sostituire
#     `pip install -e .` con:
#       pip install -r requirements-android.lock.txt -e . --no-deps
#     NB: i pin qui derivano da Python 3.14 (.venv-test); la matrice CI usa
#     3.11/3.12. Verificare la disponibilità delle wheel su quelle versioni
#     prima di attivare lo step (per questo il cambio a ci.yml è lasciato fuori).
